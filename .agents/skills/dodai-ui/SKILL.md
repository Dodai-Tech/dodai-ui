# dodai-ui

General design-system principles live in the `design-system-guidelines` skill; read it for any component, token or theming decision. This file is the repo-specific map and runbook.

## Rules
- Repo `/Users/EBEMXC4/Projects/dodai-ui`. Commit and push to `origin HEAD`. Never publish crates without the user's go-ahead (`just publish-dry` is safe; order in `scripts/lib/versioning.nu` `publish-order`: dodai-fx/core → icons/charts-core/shaders → toolkits). One workspace version for every crate: `nu scripts/bump_version.nu X.Y.Z` (BOM style); `crates/dodai-freya` and `tools/shaders-kernels` have literal versions. Ask before touching other repos (droidkraft, gitkraft, pi-tokenburn).
- **No Python in the repo; all scripting is nushell.** Throwaway python3 heredocs only for your own edits (use `assert`).
- **gpui is the reference toolkit and is finished for all four designs; egui is ported.** Other toolkits (iced, slint, leptos, dioxus, yew, ratatui, bevy, freya) and `dist/` only get tokens and tuning when the user asks for a port.
- Separation (verified): designs depend only on `dodai-core` (plus their own optional icon crate); core knows no design; no component, toolkit or shared test reads a theme id or family. `themes::systems()` is the only registry. Style comes from tokens, `ShapeSystem`, `DesignSpec` hooks and `Look` flags. Cyberpunk is described only as "cyberpunk-inspired".
- User prefs: terse, iterative, autonomous. Typed names, tokenized values, no duplicate components, breaking changes OK. Readable, labelled showcase UI (label column + control + hint; `Segmented` for pickers). For visual bugs take screenshots yourself and verify. Report honestly what was and wasn't verified (clicks, keys and hover can't be driven).

## Gate (before every commit; read the output, stop on failure)
```
cargo fmt --all && (cd crates/dodai-freya && cargo fmt)   # freya is its own workspace
# Whole-workspace all-features builds fail (iced naga vs gpui naga): go per crate.

cargo test -q -p dodai-gpui -p dodai-charts-core -p dodai-gpui-charts -p dodai-showcase [-p ...] --all-features
cargo build -q --example gpui_showcase
cargo check -q -p dodai-egui -p dodai-iced -p dodai-slint -p dodai-leptos -p dodai-dioxus -p dodai-ratatui -p dodai-yew -p dodai-topcoat   # big commits / core changes
nu scripts/tests/run_all.nu
just check-gpui-features          # feature slices must each compile warning-free
(cd fuzz && cargo check --bins)   # after public struct changes
(cd crates/dodai-freya && cargo clippy --locked --all-targets -- -D warnings && cargo test --locked)
```
- Showcase snippets (`snippets.rs`) are kept compiled by naming each fn in a `const _` block; add new snippet fns there (no `allow(dead_code)`).
- `tests/no_raw_colours.rs` also scans `dodai-gpui-charts`; justified literals go into its `ALLOWED` list with a reason. Run `cargo test -p dodai-gpui` after chart edits, not only the charts crate.
- Docs are `-D warnings` in CI: `RUSTDOCFLAGS="-D warnings" cargo doc --no-deps -p <crate>` (inner links inside `dodai-core` use `crate::`).
- Never chain `add && commit && push` after a gate whose output you haven't read. Commit message: one descriptive line; unrelated work in separate commits.
- Edits: `cargo fmt` reflows code, so exact-string replace breaks. Use a whitespace-tolerant python helper that asserts the match count (throwaway, outside the repo), or perl `-0pi`. Don't split a doc comment from its item; when appending tests check which `mod tests` they land in.
- Token/CSS/export change: `cargo run -q -p dodai-topcoat --example export -- dist && rm -rf crates/dist`. Cyberpunk token change also regenerates the Slint snapshot.
- Shader kernel change: `nu scripts/gen-kernels.nu` then `just build-kernels`. Preview: `cargo run -q --release -p dodai-shaders --example dump -- /tmp/dump 1.5`. Kernel rules: `fn(uv: Vec2, c: &Ctx) -> Vec3`, no iterators over arrays/strings, no `u8`/`u64`, no early returns in post kernels.
- New `ButtonVariant`: update `crates/dodai-slint/tests/tokens.rs`, regenerate `theme.slint` (`cargo run -q -p dodai-slint --example slint_gen > crates/dodai-slint/ui/theme.slint`), CSS, all specs.
- `.cargo/audit.toml` is tracked: never overwrite with `>`.
- After adding a token, `Look`/`ShapeStyle` field or enum variant, rerun clippy and tests (non-exhaustive matches, struct literals such as the `SurfaceFx` literal in `showcase_smoke.rs`). `cargo fmt` reformats: re-read before string-replacing.

## gpui gotchas
- Types from `dodai_gpui` are fully qualified in the showcase `main.rs` (compiled twice). `tests/no_raw_colours.rs` rejects literals like `gpui::black()` in components. In gpui tests Material is `dodai_core::material`.
- Clippy traps: `type_complexity` (use `type` aliases), `clone_on_copy`, `unused_mut`, `needless_borrow`, `needless_range_loop`, `items_after_test_module`, `double_ended_iterator_last`.
- API facts for gpui 0.2.2: `Window::focus(&handle)` takes one argument; `Div` has no `self_start` (wrap in `div().flex().child(x.flex_none())` to hug content); no custom shaders or scale/rotate transforms; `Hsla` has no `blend_with` (use `crate::motion::mix`); `.hover` ignores parent hover (use `.group`); `format!` strings need `SharedString::from` for `ElementId`; `StyledText::layout()` gives `index_for_position`/`position_for_index` (used for selectable text); `HighlightStyle.background_color` paints selections.
- More gpui 0.2.2 traps: no `flex_2`; call `track_focus` explicitly; `use gpui::prelude::FluentBuilder as _` for `.when/.when_some/.map`; never call `.id()` twice on one element; `Legend::new` takes `(SharedString, Color)`; no rotated text. Clippy caps functions at 7 args (refactor, never `allow`); a `pub(super) fn` cannot take a private type.
- Element ids are scoped by the parent id: give a chart's grid an id from `self.follow.sub("x")` so two instances on one page don't share hover state.
- `charts::framed(&t, ticks, names, plot)` takes a plain `Div`. For a pointer-tracked plot use `common::tracked_canvas(&bounds, paint)` (stores the bounds, then paints) inside `common::plot_box(id, height, canvas)`, then `focus.pointer(plot, &bounds, hit)`.
- `interact::track(el, &state, cx)` takes `cx`: it reads the focus handle and pointer flag from the `Interact` entity and the ring from the theme. The ring *shape* still comes from `shaped_id` (thread-local `RING_SHAPE`), so call `shaped_id` inside the `track(..)` argument.
- lyon panics on non-finite points: guard every canvas path (`paint::finite`). Chart marks go through `shaped`/`ShapeStyle::from_tokens` (design-shaped, like `BarChart`), round shapes through `math::circle_points` (adaptive sides, `CIRCLE_TOLERANCE`).
- Paint clamps radii to half the shorter side. `ShapeSize::Full` is 9999. Pills are real radii (0.4 × control height) so roundness above 100% still rounds them.
- Key APIs: `Button::new(id,label).variant(..).on_click(..).corners(..).crop(Crop)`; `.surface(Surface)` on Button, IconButton, Card, Panel, Tag, TextInput, Select, Toolbar, ListItem, dialogs and sheets (precedence: component, app-wide `set_surface_fx`, design); `set_shape_tune`/`shape_tune()`; `Segmented::new(id,[labels]).selected(i).on_change(..)`; `CodeBlock::new(id, code).language(..).max_height(px).scrollbar(bool)` (selectable, Cmd/Ctrl-C and -A under key context `DodaiCode`); `ScrollArea::new(id).max_height(px).horizontal(true).scrollbar(bool)`.

## Performance (scroll jank)
- Follow the `jank-free` skill: measure, never guess. Probe: `DODAI_AUTOSCROLL=1 DODAI_CAT=n ./target/release/examples/gpui_showcase` prints `fps N worst X ms slow>12ms K` and `hitch` lines; `DODAI_PROF=1` adds root build ms and the costliest sections per second (`section_view.rs::section_prof`). Run in the background, `sleep 9`, `pkill -f examples/gpui_showcase`. Sample: `sample $PID 4 -file /tmp/x.txt` on the debug build. **No frames arrive while the display sleeps or the screen is locked** (zero fps lines): `caffeinate -u` or wait for the user. Delete `target/release` afterwards when disk is low.
- Known cause (gpui 0.2.2 `AnyView::cached`): the cache key includes window bounds, and scrolling moves them, so every realised section is fully rebuilt (render + layout + prepaint + paint) on every scroll frame; `window.refresh()` (hover/click state in divs, tooltips) defeats all caches for that frame. Scroll cost = build cost of realised sections + the root view (re-rendered and laid out every scroll frame).
- Measured fixes (all categories now ~0-0.5 slow frames/s while autoscrolling; remaining: one-off first builds of 5-15 ms, and rare 100-800 ms stalls in `CAMetalLayer nextDrawable`, i.e. system/display, not app code):
  - Keep the root small: the sidebar is a cached `SidebarView` (does not move on scroll, so gpui replays it; the root notifies it only when the scroll-spy changes); the overview is one child virtualised like a section (spacer of its last height when scrolled away).
  - Small realisation margin (`max(0.2 vp, 200 px)`); at most one *new* off-screen section per frame; measure-ahead of unmeasured sections only when the page has rested (`REST` = 200 ms after `scrolled_at`), one per frame; while scrolling a single timer (`rest_pending`) wakes the page when it rests instead of re-rendering every frame.
  - Frame requests that change nothing (autoscroll, unmeasured) go through `next_frame_quiet` (sets `quiet` so section/sidebar observers skip the rebuild); `request_animation_frame` notifies as a real change.
  - Demo ticks ride `cx.on_next_frame` via `Showcase::tick_demos` and rebuild only `live_sections`; never a free-running timer.
  - Per element: taffy + text measuring dominate (`TextLayout::layout`, `shape_text`, `line_wrapper`), not drawing. Avoid gpui `.truncate()` in big lists (re-truncates every measure; shorten once). Paint many labels on one canvas (`charts::slot_labels`, `CanvasText`) instead of a flex row of text nodes. `Icon` is a single sized canvas with a cached `Mesh` (tessellated once, replayed with `Path::push_triangle`).
- Profiling: release is `strip = "symbols"`; for readable samples build with `CARGO_PROFILE_RELEASE_STRIP=none CARGO_PROFILE_RELEASE_DEBUG=line-tables-only`. Attribute with a perl stack walk over `sample` output (indent = depth). `DODAI_PROF=1` prints per-section ms and `slow section <title>: N ms` for single builds over 3 ms.
- Disk fills fast (release ~4 GB, debug incremental ~12 GB): a garbled "failed to parse process output … rustc" error means the disk is full; `rm -rf target/debug/incremental fuzz/target target/release`.
- Screenshot base64 over ~55 KB fails inline: `sips -Z 760 -s format jpeg -s formatOptions 45`. `sips -c` with `--cropOffset` can silently ignore the offset: verify the crop.
- Showcase structure: each section is a cached `SectionView`; scroll-wheel sets `Showcase.quiet` to skip rebuilds; `built`/`real_h`/`section_group` maps in `main.rs`.
